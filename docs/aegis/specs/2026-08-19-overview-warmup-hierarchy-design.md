# 系统概览暖服层级展示设计

## 目标

在系统概览中按 Target Server 聚合当前暖服任务，使运维人员能一眼看出同一目标服务器上并行运行的多个 Warm-up Agent，以及每个节点各自的大厅状态和计时。

## 基线与范围

- 基线：`frontend/src/components/OverviewView.tsx` 当前以单层表格渲染 `attempts`；`ApiService.fetchAllState` 已将 `/v1/warmups` 与 A2S observations 合并为前端 `WarmupAttempt` 和 `TargetServer`。
- 数据关系：一个 Target Server 可有多条 `active` 或 `uncertain` 暖服任务；每条任务对应一个 Warm-up Agent 和一个可选的大厅 ID。
- 本次只改系统概览的暖服任务区域及其前端测试。不改 Core API、调度策略、目标服务器页和暖服节点页。

## 方案选择

采用固定展开的两层树状表格。

- 父行按目标服务器分组，避免同一服务器在多条并行暖服任务中重复出现。
- 子行保持全部展开，适合需要同时核对全部暖服节点的运维场景。
- 同一组内的子行按开始时间倒序，组的顺序由其最新任务开始时间决定。

未采用可折叠分组，因为会增加检查并发暖服状态的操作；未采用父卡片和嵌套表，因为在多服务器、多节点时信息密度较低。

## 展示与交互

每个父行显示：

- `服务器[n]` 和服务器名称或端点；若有名称，端点作为辅助信息。
- 运行模式。节点模式不一致时显示“混合模式”，避免给出错误的单一模式。
- 当前调度节点数，即该服务器分组内任务数。
- A2S 当前人数，格式为 `playerCount/maxPlayers`；无可用人数观测时显示 `--`。
- 保留现有“定位服务器”操作，点击进入目标服务器页。

每个子行显示：

- `暖服节点[n]` 和节点名称。
- 当前状态与当前阶段。
- 大厅 ID、剩余时间和开始时间。

子行使用左侧连接线、缩进和低对比度底色表达从属关系，不在父行重复节点字段。大厅 ID 仍只是文本，不增加复制或新操作。空状态仍显示“暂无暖服任务记录”。

## 数据流与兼容性

`OverviewView` 使用现有 `targets` 查找每个任务对应的 A2S 人数，使用 `attempts` 进行客户端分组；不新增网络请求、字段或持久化状态。`active` 与 `uncertain` 均保留在分组内，以免未确认任务被隐藏。

现有单节点服务器将渲染一个父行和一个子行。未知目标服务器的任务仍可显示，父行回退到任务携带的端点，人数显示 `--`。

## 测试与验收

扩展 `OverviewView` 测试，覆盖：

- 同一目标服务器的两条任务只产生一个服务器父项和两个暖服节点子项。
- 父项显示节点数、A2S 人数和运行模式。
- 子项保留阶段、大厅 ID、剩余时间和开始时间。
- 现有大厅 ID 的普通文本展示保持不变。

执行目标 Vitest、完整前端测试、生产构建和 `git diff --check`。视觉验收确认多节点不会挤压或重叠，窄屏下表格可横向滚动。

## 非目标

- 不添加折叠、筛选、复制大厅 ID 或按节点进行操作。
- 不更改暖服历史的可见范围；仍只显示 `/v1/warmups` 返回的 active/uncertain 任务。
- 不调整后端接口或 A2S 采样频率。

## 影响说明

影响层为管理前端的系统概览和相关组件测试。前端 API 映射、Core Controller、Warm-up Agent 和既有页面不受影响；兼容边界为现有 `WarmupAttempt` 与 `TargetServer` 类型不变。
