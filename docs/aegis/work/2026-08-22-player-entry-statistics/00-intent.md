# 玩家进入统计任务意图

## 请求结果

在 Core 管理前端增加暖服 Agent 玩家进入统计：按成功 `ReplyJoinData` 响应计数，按上海时间展示趋势与整日规律，按 Agent、下载区域、大厅类型、目标模式和 Target Server 过滤，并计算实际范围内平均每小时进入。

## 范围

- Steam Probe 成功发送后的事件采集。
- Agent 有界队列、批量上报、失败可丢语义。
- Core 独立上报认证、幂等事件存储、180 天清理和统计查询 API。
- 现用 React 管理页的入口、筛选、图表、表格和状态。

## 非目标

- 不保存 Steam ID，不统计真实进服或去重玩家数。
- 不把运行时探测区域当成显式配置写入事件。
- 不改变既有暖服调度、Steam 协议、管理 token 和大厅生命周期。

## 风险提示

- 统计上报是 best-effort，Agent 重启、队列满、超时和传输失败可能造成漏记。
- 查询原始数据最多保留 180 天；统计页面按数据库聚合避免全量事件载入内存。
- Docker/Testcontainers 不可用时，PostgreSQL 运行时聚合和迁移 smoke test 只能保留为未验证项。
