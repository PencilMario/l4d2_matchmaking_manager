# L4D2 匹配管理后台前端重建设计

## 目标

重建 `frontend/` 的 React 管理后台，保留现有 Core API 契约、数据模型、Bearer 鉴权和每 5 秒轮询机制。界面是桌面优先的紧凑工作台，最低适配 1280x720，并保证 1440x900、1920x1080 不出现横向溢出、文字重叠或布局跳动。

## 视觉方向

- 浅灰工作区，白色表面，深灰固定左导航。
- 蓝色用于常规交互，绿色正常，黄色警告，红色危险；状态不能只依赖颜色。
- 以表格、工具栏、抽屉、确认对话框为核心，不使用满屏悬浮卡片或卡片嵌套。
- 圆角不超过 8px，克制阴影，无玻璃拟态、霓虹、游戏启动器风格。
- 不使用 Canvas、WebGL、Three.js、3D、动态背景、鼠标特效或装饰动画。
- 仅保留加载、刷新、展开、行级操作等轻量 CSS 动画，遵循 `prefers-reduced-motion`。
- 图标使用 `lucide-react`；纯图标按钮必须有中文 `aria-label` 和 tooltip。

## 应用结构

左侧固定导航：

1. 系统概览
2. 目标服务器
3. 暖服节点
4. 大厅查询

顶部状态栏：

- 控制服务正常 / 连接异常。
- 最后更新于 `HH:mm:ss`。
- 手动刷新图标按钮。
- 退出当前令牌会话图标按钮。

主区域：

- 每页只有一个中文主标题，不能使用英文眉题、全大写栏目名或“小英文 + 大标题”。
- 内容优先采用工具栏和数据表。
- 服务器详情与编辑放右侧抽屉。
- 危险操作放简洁确认对话框。

## 登录和加载

登录页：

- 标题：`L4D2 匹配管理`。
- 字段：`访问令牌`。
- 支持显示/隐藏令牌。
- 空值禁用提交。
- 提交中显示“正在连接”。
- 401 清除令牌并回登录页。

首次进入：

- 服务器、节点、暖服任务、观测数据全部返回前，只显示加载界面。
- 文案：`正在读取控制服务数据`。
- 后续自动刷新不能清空现有表格、重置筛选或改变滚动位置。

## 系统概览

摘要数字：

- 正在进行的暖服任务。
- 结果未确认的任务。
- A2S 不可用服务器。
- 在线目标服务器。
- 运行中的暖服节点。
- 已隔离节点。

暖服任务表：

- 目标服务器，可点击跳转并定位服务器。
- 暖服节点。
- 运行模式。
- 当前状态。
- 当前阶段。
- 大厅 ID。
- 剩余时间。
- 开始时间。

状态转换为中文。未知状态显示“未知状态”，并以 title 或次要文本保留原始值。

人工处理区：

- `uncertain` 暖服任务提示人工检查。
- A2S 不可用服务器提示检查地址和网络。

## 目标服务器

页面标题：`目标服务器`

工具栏：

- 新增服务器。
- 搜索服务器名称或地址。
- 状态筛选：全部、在线、不可用、等待观测。
- 调度筛选：全部、已启用、已禁用。
- 手动刷新。

表格列：

- 服务器名称：优先 A2S 名称，否则显示服务器地址。
- 服务器地址。
- 当前玩家数/最大人数。
- A2S 状态。
- 最后观测时间。
- 调度状态。
- 调度优先级。
- 最大并发暖服数。
- 正在进行的暖服数。
- 操作。

表格行与设置按钮均可打开详情抽屉。长名称、地址、Steam ID 截断并提供完整 tooltip。

表单字段均为中文：

- 服务器地址：例 `203.0.113.10:27015`，说明支持主机名或 IPv4 加游戏端口。
- 需要大厅预留：开关。
- 模式类型：可选下拉框，仅提供未指定、`versus`、`coop`；未指定时保持现有 versus metadata。
- 启用调度：开关。
- 调度优先级：大于等于 0 的整数，数值越高越优先。
- 最大并发暖服数：普通服务器默认 36；预留服务器固定 1 并禁用输入。
- 单次暖服时限：默认 720 秒，同时显示分钟换算。
- 目标玩家数：默认 6。
- RCON 密码：只写，不回填；已有凭据显示“已配置”；清空凭据必须明确确认。

抽屉分区：

- 实时状态：服名、地址、玩家数、A2S 状态、最后观测时间。
- 调度设置：启用、预留、模式类型、优先级、并发、暖服时限、玩家目标、RCON 凭据状态。
- 关联暖服任务。
- 操作：编辑、禁用、删除。

禁用确认说明：

> 控制服务会先停止该服务器上进行中或结果未确认的暖服任务，再保存禁用状态。

删除确认说明：

> 控制服务会先停止相关暖服任务，确认停止后再删除服务器配置。

收到 `409 target_server_drain_failed`：

- 不关闭抽屉。
- 不从表格移除记录。
- 保留表单内容。
- 刷新服务器和暖服状态。
- 显示：`相关暖服任务未能全部停止，操作尚未完成，请检查任务状态后重试。`

## 暖服节点

页面标题：`暖服节点`

表格列：

- 节点名称。
- 运行状态。
- Steam 下载区域。
- noVNC 本机端口。
- 关联暖服任务数。
- 创建时间。
- 更新时间。
- 操作。

状态：

- `running` -> 运行中：停止、编辑、重建、删除。
- `stopped` / `created` -> 已停止 / 已创建：启动、编辑、重建、删除。
- `quarantined` -> 已隔离：编辑、删除，显示“需要人工检查”，不能启动或重建。

节点表单：

- 节点名称。
- Steam 下载区域。
- 空值说明：`使用 Steam 默认区域`。

重建交互：

1. 点击重建，打开确认框。
2. 明确说明“保留 Steam 登录数据和账号配置卷，只重建容器”。
3. 确认后关闭确认框，对应行显示旋转图标和“正在重建节点”。
4. 仅禁用该行的编辑、启动、停止、重建、删除。
5. 请求完成并刷新节点、暖服数据后才显示成功反馈。
6. 失败后保留行，停止加载，显示可重试中文错误。
7. 其他节点仍可操作。

## 大厅查询

页面标题：`大厅查询`

- 输入：`大厅 ID`。
- 按钮：`查询大厅`。
- 仅允许非零十进制 ID。
- 查询中显示加载图标和“正在查询”，保留输入并防止重复提交。

结果区：

- 大厅 ID。
- 所有者 Steam ID。
- 成员状态。
- 已确认成员数。
- 观测时间。
- 成员列表。
- 会话元数据。

metadata 原始 key/value 不变，表头必须用中文“键”“值”。

查询失败时：

- 有旧结果则继续显示，显著标记“结果可能已过期”。
- 成员数据不完整时显示“成员数据未确认”，不能推断成员数量。

## 工程约束

- 不改变 API 路径、字段、鉴权、响应模型或五秒轮询。
- 并行请求服务器、节点、暖服、观测。
- 建立统一的状态映射和错误映射，禁止在 JSX 中散落原始状态判断。
- CSS 分为 tokens、layout、tables、forms、feedback。
- 删除 Three.js、`postprocessing`、React Bits、VisualStage、Hyperspeed、Cubes、Spotlight、Counter、Stepper 等退休组件。
- 保留 React、Vite、TypeScript、Lucide、Vitest、Testing Library、Playwright。
- 抽屉与对话框支持 Esc 关闭、焦点可见、对话框焦点循环与关闭后的焦点恢复。

## 验收

- 登录、401、首次加载、五秒刷新不清空内容。
- 服务器新增、编辑、禁用、删除及 409 保留状态。
- 节点创建、编辑、启动、停止、重建、删除；隔离节点限制操作。
- 大厅成功、失败、旧结果过期、成员不完整。
- 1280x720、1440x900、1920x1080 截图无横向溢出。
- 无 Three.js 运行时依赖，无禁止文案。
